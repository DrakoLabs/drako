# ADR-0008: A2A v1.0 Cryptographic Identity via RFC 7515 Detached JWS + RFC 8785 JCS

- **Status:** Accepted
- **Date:** 2026-11-24

## Context

Multi-agent lateral propagation incidents (e.g., mid-2026 agent-to-agent worms) proved that topological or unverified endpoint trust is insufficient: spoofing an agent's endpoint or capabilities hijacks downstream peers. Ad-hoc JSON signature envelopes break interoperability across agent ecosystems; the Linux Foundation / AAIF **A2A Protocol v1.0** specification standardizes cryptographic agent identity via detached JWS signatures.

## Decision

Implement `drako.a2a.cards` strictly compliant with **A2A v1.0 `AgentCardSignature`**:

1. **Pre-processing & Canonicalization:** Recursively strip empty/default fields (`None`, `""`, `[]`, `{}`), exclude the top-level `signatures` array, and canonicalize with **RFC 8785 JCS** (`drako.kernel.receipts._canonical`).
2. **RFC 7515 Detached JWS (EdDSA / RFC 8037):** Sign `ASCII(b64url(protected) || '.' || b64url(jcs_payload))` with Ed25519 where `protected` encodes `{"alg": "EdDSA", "typ": "a2a-agent-card+jws", "kid": ..., "iat": ..., "exp": ...}`, storing `{"protected", "signature"}` entries in `card["signatures"]`.
3. **Operator/Target Key Separation:** Operators/CI sign `agent-card.json` offline (`drako a2a sign`); target peer agents verify offline using only the public key (`drako a2a verify`) or fetch remote cards strictly through `drako.kernel.egress.assert_public_url()`.

## Alternatives Considered

- **Custom JSON signature envelope:** Breaks interoperability with standard A2A v1.0 clients and JOSE verifiers.

## Consequences

- Signed Agent Cards generated by Drako verify cleanly across standard A2A v1.0 / RFC 7515 toolchains, with zero database dependencies.

## Verification

- `tests/test_a2a_cards.py` (roundtrip, default-stripping canonical invariance, URL/skill tamper fail-closed, expiry, `kid` mismatch, SSRF protection).
